## MC 服务端吃什么：单核性能排第一，核心数排第二

Minecraft 的大量游戏逻辑跑在主线程上。玩家跑图加载区块、刷怪塔运转、红石电路计算，这些活基本由一个核在扛。所以主频 4.5GHz 的 4 核跑 MC 服，往往比主频 2.8GHz 的 16 核更稳。TPS（服务器每秒刻数）掉不掉，主要看那个主线程的核够不够快。

雨云给的 CPU 单核性能排序是：i9-14900K > Ryzen 9 9950X > Ryzen 9 7950X > Ryzen 9 5900X > Gold 6146 > Platinum 8275CL > E5 2666v3。E5 系列单核偏弱，跑 1.18 以上的高版本要谨慎，它适合 1.12.2 这类老版本纯净服。

核心数不是完全没用。玩家数量上去、插件装得多、同时开多个世界或跨服群组时，多核才分担得过来。判断顺序是：先按单核性能挑 CPU 型号，再看人数决定核心和内存，最后按在线人数配带宽。

## 4 核 8G 是下限还是浪费？“能跑”和“跑得稳”差在这

社区里两个说法经常打架：一边是教程作者强调“服务器配置建议 4 核 8G 以上，最低不要低于 4 核 8G”，另一边是科普文说 2 核 2G 就能带 2~5 人。两个都对，说的是两件事。

2 核 2G 的实测口径是 Java 版纯净原版、给 Java 分配 1.2~1.5GB、剩下的留给系统，能承载 2~5 人在线。这是“能进去玩、不崩”的水平。加 Paper 和 Essentials、LuckPerms 这类常用插件，2GB 勉强够，但 Dynmap 这种实时地图会额外吃资源，得把刷新频率降下来。

4 核 8G 的口径是 10~15 人同时在线还比较从容。教程作者用的是 1.21 高版本加面板，高版本 Java 服对单核和内存的要求比 1.12 时代高出一截，所以他直接把 4 核 8G 定成下限。

判断标准很简单：只跟几个朋友偶尔上线、视距调低、不装模组，2 核 4G 完全够；要开一个对外开放、玩家随时进出、还想装插件做小游戏的服，按 4 核 8G 起步，别拿最低配置当推荐配置用。

**5–15 人插件服**。插件本身不重，重的是插件带来的额外计算（计分板、经济系统、领地检测）。这一档还是 2 核 4G，但 CPU 型号要选高的，i9-14900K 或 9950X 的 2 核 4G 比 E5 同配置贵几十块，值。

**50 人以上或大型整合包**。4 核 16G，i9-14900K 和 9950X 都行，后者主频略低一点但架构更新。

**基岩版**。基岩版服务端比 Java 版省资源，2 核 2G 就能容纳 10 人左右在线。雨云在售的最低档是 2 核 4G，比理论最低配高一档，但已经是表里最便宜的选择，没必要纠结。

## 内存按模组量翻倍，带宽按人数估

内存的经验值很清晰：原版服 4G 够用，轻量整合包 8G 起步，大型整合包 16G 起步。上了模组还按原版的内存给，GC 一抖，玩家看到的就是全体卡一下。带 MOD 的 Forge/Fabric 服，2GB 基本不够用，哪怕轻量模组包也容易因为内存不足频繁卡顿甚至崩溃。

带宽看上行，不看下行。开服吃的是服务器往玩家发数据的那条管道。3Mbps 上行在 6~8 人同时在线时就可能卡，10Mbps 起步比较稳；10 人以内 10M 基本够，20 人以上建议 15M 起。

硬盘选 SSD。世界读写频繁，机械硬盘会明显拖慢区块加载，玩家跑图时会看到地形一块一块地补出来。容量 50G 起步，装整合包的话 150G 更合适。

## 开服前必须确认的软件条件

**Java 版本**。MC 1.21 需要 Java 21，装完用 `java -version` 确认显示 21.x。用 Java 17 开 1.21 会直接报错起不来。

**服务端选型**。原版是官方服务端，无修改；Forge 是模组加载器和 API，模组生态最全；Fabric 更轻量、跟进新版本更快；Paper 是 Spigot 的高性能分支，兼容大部分 Bukkit/Spigot 插件，优化选项多；Mohist 融合 Forge 和 Bukkit，能同时跑模组和插件，但它只更新到 1.20.2，要开 1.21 只能用原版、Forge、Fabric 或 Paper。

**EULA**。首次启动会提示 `You need to agree to the EULA in order to run the server`，编辑 `eula.txt` 把 `false` 改成 `true` 再启动。

**server.properties**。常用几项：`max-players=20` 人数上限、`view-distance=7` 视距、`simulation-distance=5` 模拟距离、`online-mode=true` 正版验证、`white-list` 白名单、`spawn-protection=0` 出生点保护、`server-port=25565` 端口。多开服要给每个实例改不同端口。

**端口**。MC 默认 25565，MCSManager 面板需要 23333 和 24444。用 NAT 映射的机器，映射出来的外网端口每个人都不一样，别照抄教程里的数字，按自己后台显示的填。

**系统**。Linux 比 Windows 省资源。Windows 系统自身占的内存和 CPU 更多，留给 Java 的空间更少，同样配置跑出来的效果差一截。

**启动参数**。通用写法是 `java -server -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar 服务端.jar`。`-XX:MaxRAMPercentage=95.0` 限制 JVM 最多用系统内存的 95%，`-Xms128M` 设初始堆内存，`-Dfile.encoding=UTF-8` 防中文乱码。Forge 1.21 的搭法不一样，要先跑 `-installServer` 生成启动脚本，再改 `user_jvm_args.txt` 里的 `-Xmx`，最后把启动命令换成 `bash run.sh`。改 `-Xmx` 时留一点内存给系统，别把整台机器的内存全给 Java。

## 同样的配置多带 5 个人的做法

- 换 Paper 或 Purpur 核心，TPS 稳定性比原版好，内存占用也更低。
- 先调 `view-distance` 和 `simulation-distance`。视距从 10 降到 7，区块加载压力能降一大截，玩家基本感觉不出来。
- 关掉世界边界外的生成，限制怪物生成数量，降低自动存档频率。
- 地图备份、数据保存这类操作交给异步插件，别让它阻塞主线程。
- 系统选 Debian 或 Ubuntu Minimal 这类轻量发行版，关掉无关服务。
- 用 `timings` 命令看性能报告，按报告调视距和实体数量，别凭感觉乱改参数。
